Cachet Vocabulary

Version 1 · terms used in the credentialSubject and evidence of W3C Verifiable Credentials issued by Cachet.

https://w3id.org/cachet/v1#

Stability

This version is immutable. Terms may be added. A term’s meaning is never changed, and a term is never removed — term IRIs are cryptographically signed into credentials intended to verify indefinitely, offline, after the issuing institution or the Cachet platform no longer exists. Breaking changes mint a new version path (/v2).

Scope

Only domain-specific terms are minted here. Person-level properties are expressed with established vocabularies in each schema’s own context and are deliberately absent from this namespace:

Properties — academic and professional awards

TermRangeDescription
programmeuntyped Programme or field of study the award relates to.
specializationuntyped Specialization within a programme.
mentionuntyped Grade or distinction awarded, e.g. Très Bien.
sessionuntyped Academic session or year the award relates to. Values are issuer-supplied strings such as 2026, not dates.
certificateNumberuntyped The issuer’s own reference number, as printed on the certificate.
studentNumberuntyped Institution-scoped student registration number (matricule). Scoped to the issuer; not globally unique.
certificationTitleuntyped Name of a professional certification.
leveluntyped Level or tier of a professional certification.
awardDateuntyped Date a professional certification was awarded.
expiryDateuntyped Date a professional certification lapses.

Why are the date terms untyped?

Only terms whose values Cachet itself generates carry an @type. The values of awardDate, expiryDate and session come from tenant data and take whatever lexical form a registrar entered. Declaring xsd:date on a field we do not control would assert a format the data does not honour — inside a document we have signed.

Classes — evidence

TermDescription
AttendanceEvidence Evidence that a credential’s claim was derived from an attendance record whose eligibility was computed by an upstream system.

Properties — evidence

TermRangeDescription
basisuntyped The rule under which eligibility was computed: cpd, hours, or attendance.
computedBy@id Identifier of the system that computed eligibility. An HTTPS origin, not a DID — see the note below.
sourceRefuntyped Opaque reference to the upstream record, of the form <activity>:<participant>. Used for idempotency on re-import.
hoursAttendedxsd:decimal Hours of attendance the eligibility computation was based on. Absent when the upstream record does not carry it — never null.
recordedAtxsd:dateTime When the evidence was retrieved from the upstream system. Not when the underlying activity took place.

What evidence does and does not prove.

The evidence object is signed by the issuer’s key. It therefore proves that the issuer asserts this basis for the claim. It does not prove that the system named in computedBy independently attested to anything.

That is why computedBy is an HTTPS origin rather than a DID: a DID would imply a resolvable, key-backed identity capable of making its own verifiable statements. An independently-verifiable upstream attestation requires that system to sign its own payload and for that signed object to be embedded here — a future extension.

Machine-readable context

The JSON-LD context is served from this same IRI under content negotiation (Accept: application/ld+json), and is also available at v1.jsonld.

Credentials issued by Cachet embed these term definitions inline in their @context. Nothing dereferences this document at issuance or verification time, which is what allows a Cachet credential to be verified offline from a printed QR code with no network access. This page is a canonical definition for humans and for tools that follow the IRI — documentation with a URL, not a runtime dependency.

In this document the namespace is bound to the prefix cachet:; in issued credentials it is bound to certificate:. Prefix names are local to a document and both expand to the same IRI. The IRI is what is signed.
